# سجل العيوب

احتفظ بالعيوب المحلولة مع سببها ودليل تحققها. لا تضع بيانات عمال حقيقية أو أسرارًا هنا.

## مفتوحة

### B-009 — نافذة تغيير كلمة المرور لا توضح سبب الرفض

- **العَرَض:** إذا كانت كلمة التغيير أقل من 8 أحرف أو لم يطابق التأكيد،
  تبقى النافذة مفتوحة دون رسالة ظاهرة.
- **السبب:** شرط الواجهة ينهي الإجراء مبكرًا دون تعيين رسالة تحقق؛ المستودع
  يشترط طولًا لا يقل عن 8 أحرف بعد إزالة الفراغات الطرفية.
- **الحل المؤقت:** استخدم 8 أحرف أو أكثر واكتب القيمة نفسها في التأكيد.
- **الحالة:** أفاد المالك لاحقًا أن تغيير كلمة المرور اشتغل وطلب عدم تعديل
  التطبيق. يظل تحسين رسالة الرفض مفتوحًا، ولا ينفذ إلا بطلب جديد.
- **التحقق:** مراجعة `auth_gate.dart` و`local_auth_repository.dart`؛ لم يطبق
  إصلاح ولم يبن APK جديد لهذا التغيير.

### B-010 — رفض CSV بسبب الترميز

- **العَرَض:** أعمدة ملف القوى سليمة لكن الاستيراد يعرض خطأ الملف غير صالح.
- **السبب:** الملف المفحوص Windows-1256 بينما المحلل يشترط UTF-8.
- **الحل المؤقت:** أعد تصدير الملف من LibreOffice كـText CSV بترميز Unicode
  (UTF-8)، وفاصل الحقول comma `,`، ومحدد النص `"`. CSV يصدر الورقة النشطة
  فقط؛ اختر ورقة القوى الكاملة قبل الحفظ.
- **الخصوصية:** لا تنسخ ملف القوى إلى المستودع أو docs.

### B-002 — ADB لا يصل إلى مجلد إعداد Android للمستخدم

- **العَرَض:** ADB لا يبدأ تعداد الأجهزة لأنه لا يستطيع إنشاء `.android` في المسار الافتراضي.
- **النطاق:** بيئة التطوير؛ لا يدل وحده على خلل بالتطبيق. تثبيت الجهاز غير متحقق.
- **المحاولة:** متغيرات Android المؤقتة لم تغير مسار ADB الأصلي، وإنشاء مجلد الجذر رُفض.
- **الخطوة التالية:** استخدم ADB من CMD في حساب Windows المعتاد لدى المالك عند الحاجة.

## محلولة

### B-011 — Windows Smart App Control يمنع تشغيل gen_snapshot أثناء بناء armeabi-v7a

- **العَرَض:** ظهور خطأ ProcessException: An Application Control policy has blocked this file عند محاولة تشغيل lutter build apk مباشرة في PowerShell؛ يمنع Windows سياسة التطبيقات (Smart App Control / WDAC) من تنفيذ gen_snapshot.exe في مجلد engine\\android-arm-release.
- **السبب:** تفعيل Smart App Control (SAC) في نظام Windows 11 وحظره للملفات التنفيذية غير الموقعة في كاش محرك Flutter عند استدعائها عبر Dart VM.
- **الحل:** بناء الـ Release عبر سكربت البيئة المعزول work\\flutter-profile\\android-env.cmd مع lutter build apk --release --no-pub، أو البناء المخصص للأجهزة الحديثة ARM64 (--target-platform android-arm64)، أو إضافة استثناء لمجلد C:\\src\\flutter في Windows Defender.
- **التحقق:** اكتمل البناء بنجاح وأُنتج الملف outputs/Radar Labour.apk بحجم 70,029,527 بايت.

### B-005 — قيود اختبار Flutter على Temp والاتصال المحلي

- **العَرَض:** محاولة الاختبار الأولى فشلت في نسخ listener إلى Temp، ثم ظهرت
  أخطاء SocketException على 127.0.0.1؛ لم تكن أخطاء كود.
- **الإصلاح:** تشغيل Flutter عبر `work/flutter-profile/android-env.cmd`، ثم
  تهيئة صلاحية تشغيل الـtest isolate المحلي. لم نغيّر كود التطبيق للسماح بالشبكة.
- **التحقق:** `flutter test --no-pub` نجح 73/73.

### B-008 — ترحيل supplier مكرر واختبارات معمارية

- **العَرَض:** v1→v3 حاول إضافة عمود supplier مرتين، واختبارات المعمارية
  رفضت اعتماد طبقة العرض على طبقة قاعدة البيانات وfeature آخر.
- **الإصلاح:** أضيف supplier فقط لمسار v2→v3، ونقلت التنسيق إلى app composition
  layer؛ حفظ المستودعات عبر controller وعقود feature.
- **التحقق:** اختبارات migration والمعمارية نجحت ضمن 73/73، والتحليل نظيف.

### B-007 — نسخة roster شخصية داخل docs

- **العَرَض:** وُجد ملف محلي غير متتبع `docs/database.csv` يحتوي أعمدة رقم
  الهوية والاسم وبيانات عمال.
- **الإصلاح:** إزالة نسخة roster من `docs` وتسجيل المشكلة دون الاحتفاظ بأي
  أسماء أو أرقام هوية في سجل الأخطاء.
- **التحقق:** الملف غير موجود بعد الإزالة، ولم يُسجل محتواه الشخصي في Git أو
  التقرير.

### B-006 — أخطاء تركيب بعد نقل منسق الرسالة إلى domain

- **العَرَض:** formatter وجد قوس إغلاق ناقصًا، ثم أظهر Dart analyzer تعارضًا
  بين قائمة نصوص قديمة وقيم domain التي تحتوي معرّف العامل ونصه.
- **الإصلاح:** إزالة بقايا الامتداد القديم، واستخدام سجل typed يحوي `id` و`label`
  من domain إلى إعداد الملخص. بعد إدخال عقد المستودع أضيفت وسوم `@override`
  للأعضاء المنفذة لإزالة ملاحظات analyzer.
- **التحقق:** `dart format` اكتمل و`dart analyze` أعاد `No issues found`. اختبارات
  Flutter المضافة لم تبدأ بسبب B-005؛ اجتاز منسق الرسالة تحقق Dart مباشرًا
  لحالة حضور إنجليزية مختارة، ولا يُدّعى نجاح مجموعة Flutter بعد.

### B-004 — أخطاء تحليل واختبارات عند إكمال S6

- **العَرَض:** analyzer لم يجد `EventType`/`EventAction` في ملف ربط التطبيق، ثم
  ظهرت ملاحظات lint؛ الاختبار الأول لمستودع لوحة التغطية لم يترجم.
- **السبب:** import لنماذج الأحداث مفقود، وبعض عناصر/شروط Dart تحتاج الصياغة
  المعتمدة، وconstructors Drift المولدة لا تقبل `const`.
- **الإصلاح:** إضافة import النماذج وتصحيح صياغة lint وإزالة `const` من بيانات
  اختبار Drift، وترتيب `part` directives قبل التعريفات.
- **التحقق:** `flutter analyze --no-pub` بلا أي issue، واختباران جديدان نجحا؛
  مجموعة الاختبارات كلها 66/66، ثم نجح بناء APK Release.

### B-001 — شاشة التطبيق البيضاء بعد التثبيت

- **العَرَض:** عند تشغيل النسخة القديمة ظهرت شاشة بيضاء.
- **السبب:** جذر Flutter كان يعرض `MaterialApp` بداخله `Scaffold` فارغًا.
- **الإصلاح البرمجي:** أضيفت حالات تحميل وخطأ وإعادة محاولة، ثم لوحة ثنائية اللغة وتنقل وشاشات محلية للعمال والفرق والسكن.
- **دليل الإغلاق:** في 23 أكتوبر 2026 أرسل المالك ست لقطات بعد تثبيت APK الذي بُني الساعة 08:28؛ تظهر لوحة البداية والتنقل إلى العمال وإضافة عامل والفرق والسكن والإعدادات، ولا تظهر شاشة بيضاء. القوائم الفارغة متوقعة قبل إضافة البيانات. تجربة الوظائف الجديدة المضافة بعد هذا APK لا تزال مطلوبة.

### B-003 — بناء APK محدث يفشل في Gradle

- **العَرَض:** ظهرت `The settings are not yet available for build`، ثم مشكلات وصول SDK وPub ومجلد Kotlin المؤقت.
- **السبب:** عملية Gradle لم تستطع دخول مجلد Flutter SDK لاستدعاء Git، ثم واجهت صلاحيات الكتابة في كاش Gradle/Pub وغياب ملف rollback مؤقت من sandbox.
- **الإصلاح:** مُنح الوصول المحدد لمجلد Flutter SDK وكاشات Gradle وPub، وأزيل تكرار متغير Android القديم، ووُجه TEMP/TMP و`java.io.tmpdir` إلى مجلد scratch محلي.
- **التحقق:** نجح بناء Release في 23 أكتوبر 2026. `aapt` أكد اسم التطبيق العربي وعدم وجود INTERNET أو ACCESS_NETWORK_STATE في الحزمة. تفاصيل SHA-256 في `WORKLOG.md`.
