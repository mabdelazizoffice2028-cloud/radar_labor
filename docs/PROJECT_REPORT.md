# تقرير حالة وتنفيذ رادار ليبور

**آخر تحديث:** 23 أكتوبر 2026  
**المستودع المحلي:** `C:\my_apps\radar_labor`  
**الهدف:** تطبيق هاتف ميداني عربي/إنجليزي، محلي دون إنترنت وقت التشغيل، بأصول محلية وتخزين مشفّر.

## ملخص تنفيذي

كان التطبيق عند بداية هذه المرحلة يعرض شاشة فارغة لأن نقطة الدخول كانت `Scaffold` خاليًا. تم استبدالها بمسار إقلاع يظهر التحميل أو الخطأ وإعادة المحاولة، ثم واجهة Material 3 فيها لوحة رئيسية وتنقل عربي/إنجليزي وشاشات محلية لإضافة العمال والفرق والسكن وتسجيل بعض أحداث اليوم. قاعدة البيانات أصبحت تفتح من مجلد بيانات التطبيق بمفتاح مولّد ومحفوظ عبر التخزين الآمن، والخط Cairo وأيقونات Material محلية ضمن الحزمة.

هذه **نسخة تطبيق أولية** وليست إنهاءً لكل متطلبات التشغيل في PRD. توجد نواة التاريخ والأحداث ومحرك الحالات والجداول، لكن تفاعل الواجهة وعرض الحالات وسير السكن والموقع والتبريرات والتقارير لم يكتمل. لا يوجد دليل بعد على تثبيت APK الجديد وتشغيله على هاتف، كما أن APK الموجود أقدم من آخر التعديلات. لذلك لا يعتبر هذا التقرير إعلان إصدار نهائي.

## ما تغير

### نقطة الدخول وتجربة الاستخدام

- أزيلت الواجهة البيضاء الفارغة.
- أصبح بدء التشغيل يفتح التخزين الآمن وقاعدة البيانات المشفرة، مع مؤشر تحميل وشاشة خطأ قابلة لإعادة المحاولة عند الفشل.
- أضيفت واجهة Material 3 بألوان زرقاء ومسافات كبيرة وتصفح سفلي، ودعم العربية RTL والإنجليزية مع حفظ اختيار اللغة محليًا.
- أضيفت لوحة تعرض تاريخ العمل وعدد العمال النشطين، وصفحات العمال والفرق والسكن والإعدادات.
- إضافة العامل تتضمن رقمًا فريدًا واسمًا عربيًا واسمًا إنجليزيًا وإسنادًا اختياريًا لفريق وسكن. تسجيل الموقع يشترط فريقًا، وتسجيل غياب السكن يشترط سكنًا.
- أحداث الموقع والغياب تحفظ محليًا مع معرّف الجهاز والتسلسل وتاريخ العمل.

### التخزين المحلي والأصول

- قاعدة البيانات Drift/SQLite مشفرة بمفتاح عشوائي 256-bit محفوظ عبر Flutter Secure Storage.
- أضيفت جداول العمال والفرق والسكن وفترات العمل والأحداث وترحيل مخطط قاعدة البيانات من v1 إلى v2.
- خط Cairo متغير محلي مع رخصة OFL والإسناد في `assets/fonts/`. أيقونات Material تستخدم الخط المضمن في Flutter.
- إزالة تبعيات Supabase والاتصال التي كانت في الخطة السابقة؛ المزامنة مؤجلة بقرار المالك. عُدّل Manifest لمنع دمج INTERNET وACCESS_NETWORK_STATE في Release. نسخة Debug قد تحصل على INTERNET من إعداد Flutter لخدمة VM أثناء التطوير.
- لا تُحمّل الواجهة خطًا أو صورة أو أيقونة من الإنترنت عند التشغيل.

### النواة والوثائق

- توجد نماذج الأحداث والحالات ومحرك حالة نقي وحساب يوم العمل في توقيت الرياض مع حد الساعة 03:00.
- يوجد مستودع أحداث append-only بمعاملة وتسلسل جهاز، ومستودع إعدادات محلي.
- حدث README العربي/الإنجليزي ليعرض الميزات الحقيقية والنواقص، وأعيد تحديث خارطة الطريق والتسليم وسجل العيوب والعمل.
- سجل الجداول المصدر محفوظ في مجلد قاعدة البيانات. يجب التأكد من وجود تعريف Drift للمخطط v2 بعد مراجعة آخر الملفات المولدة.

## الميزات التي ما زالت مطلوبة قبل اعتبار V1 جاهزًا

1. تشخيص Gradle وإنتاج APK حديث. فحص اسم التطبيق والأذونات والأصل والخط والحجم والتوقيع.
2. تثبيت حزمة Release على هاتف، فتح التطبيق بعد تثبيت نظيف وبعد إعادة فتح، والتحقق من العربية/الإنجليزية ووضع الطيران وحفظ البيانات.
3. إكمال واجهة تسجيل السكن: اختيار المبنى، فحص العاملين، الغائبون، إرسال الفحص فارغًا عند الحاجة، تصحيح/تراجع كسجل جديد.
4. إكمال سير الموقع حسب الفريق والإرسال والإحصاءات وتسجيل التصحيحات.
5. ربط `StatusEngine` بلوحة تعرض حالات العمال والقواعد والتعارضات والتأخر والمجهول وغير المسجل، مع التبرير والحسم حسب PRD.
6. إكمال تعديل البيانات المرجعية، فترات التوظيف والتصنيفات والواجهات التفصيلية والملخص/التصدير وفق النطاق المعتمد.
7. إعادة الفحوصات الآلية الشاملة وتحديث `ROADMAP.md` و`BUGS.md` و`WORKLOG.md` بعد كل دفعة.
8. إنهاء الرفع إلى مستودع GitHub الذي طلبه المالك، وتحديث README ووصف المستودع والمواضيع. المستودع عام بحسب بيانات المرحلة السابقة؛ لا تغيّر الخصوصية دون طلب المالك.
9. قبل النشر: تثبيت `applicationId` النهائي ومفتاح توقيع إنتاجي ونسخ احتياطية/استعادة موثقة واختيار الترخيص مع المالك.
