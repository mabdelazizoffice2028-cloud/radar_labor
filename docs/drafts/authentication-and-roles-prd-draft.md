# مسودة PRD — الدخول المحلي والأدوار وربط القوى

**الحالة:** أساس تنفيذ معتمد بتوجيه المالك في 23 أكتوبر 2026. يحل التوجيه الأخير محل أي انتظار لتجربة S6 أو طلب موافقات إضافية على التفاصيل التنفيذية.

## 1. الهدف

إضافة دخول محلي بسيط يثبت هوية المستخدم ويعرض له الإجراءات المسموحة فقط. التطبيق يظل يعمل دون إنترنت، وتُحفظ الحسابات محليًا داخل قاعدة البيانات المشفرة. لا تهيئة Supabase ولا رفع أسماء العاملين أو الحسابات إلى خدمة سحابية ضمن القرار الحالي.

## 2. الأدوار والصلاحيات

| المسمى في واجهة الدخول | الدور الداخلي المقترح | النطاق |
| --- | --- | --- |
| مدير المشروع | إدارة | لوحة جميع المواقع، العمال والمراجع، المستخدمون، التبرير والتسويات |
| HR / الإدارة | إدارة | نفس أذونات إدارة PRD. يمكن لاحقًا فصل العرض عن الإدارة إن طلب المالك |
| مشرف سكن | مشرف سكن | مساكن معيّنة فقط؛ فحص اليوم، الغياب، وتلخيص السكن |
| مشرف موقع | مشرف موقع | فرق/مواقع معيّنة فقط؛ تحديد الحاضرين وتسجيل الفريق |
| مشاهد فقط | مراقب | قراءة اللوحة فقط بلا حفظ أو تعديل |

لا يختار المستخدم دوره وقت الدخول. يختار حسابًا من قائمة حسابات نشطة، ويُستنتج الدور ونطاق السكن/الفريق من الحساب المحلي؛ كل عمليات الكتابة تُعاد حمايتها في طبقة البيانات، لا بمجرد إخفاء الأزرار.

## 3. إدارة الحسابات الأولية

- كلمة البداية `123456` لكل الحسابات، مؤقتة ويجب تغييرها عند أول دخول؛ تغييرها متاح من الإعدادات.
- لا يُخزن النص الصريح أبدًا. استخدم Argon2id المتاح عبر حزمة `cryptography` المثبتة، مع salt عشوائي ومعاملات موثقة، في Isolate لتفادي تجميد الواجهة. قارن الهاش بزمن ثابت بقدر ما تسمح به واجهة الحزمة. حد المحاولات على الجهاز وزمن تأخير تدريجي.
- مدخل الحساب قائمة منسدلة بأسماء الحسابات النشطة، ثم حقل كلمة المرور. لا يوجد إنشاء ذاتي للحسابات.
- يُنشأ حسابا مدير المشروع وHR مسبقًا بالاسمين/السجلين المحددين في المصدر المعتمد، ويُربطان بالدور الداخلي «إدارة». لا تخمّن الأسماء إذا لم تكن موجودة بوضوح.
- حسابات مشرفي السكن والموقع تختار أسماءها من القائمة المرجعية، ثم يُسند المشرف إلى سكن واحد أو أكثر أو فريق/فرق معتمدة من الإدارة. لا يسمح للمشرف بتغيير النطاق.

## 4. مصدر القوى وملف Excel

فُحصت بنية الملف المقدم دون نسخ بيانات الأشخاص إلى Git أو سجل العمل. ورقة `All Labour Active` تحتوي أعمدة: `S/O`, `ID No.`, `Name`, `Designation`, `Supplier` وصفوفًا نشطة. بقية الأوراق تشمل قوة عامة وعمال شركة وعمال مورد ومعدات.

- الملف لا يبيّن في الورقة النشطة إسناد الشخص إلى campus/housing أو site/team؛ لذلك لا يكفي وحده لتعيين صلاحيات المشرفين. يلزم إسناد منفصل صريح.
- **ممنوع استيراد `ID No.`/رقم الإقامة إلى الهاتف** وفق `CLAUDE.md`. لا ندرج ملف Excel نفسه أو أسماء الأشخاص في Git.
- القرار المتوافق مع وضع التطبيق offline: استيراد محلي على جهاز الإدارة إلى قاعدة مشفرة بعد معاينة، ثم اختيار أسماء المشرفين وإسناد المواقع/المساكن. بيانات العمال يمكن أن تبقى مراجع محلية؛ لا تستخدم Supabase ما دام قرار عدم الشبكة قائمًا.
- لا تستخدم `S/O` كمعرّف طويل الأجل قبل أن يؤكد المالك أنه ثابت بين تحديثات الملف. الخيار المفضل إضافة `employee_code` داخلي ثابت عند الاستيراد أو مطابقة السجلات بوسيلة غير حساسة مع تقرير تكرارات للمراجعة.
- استيراد XLSX محلي يحتاج حزمة قراءة XLSX/اختيار ملف جديدة؛ لم تُضف أي حزمة. احصل على موافقة منفصلة على الحزم والإصدارات بحسب `CLAUDE.md` قبل كتابة المستورد.
- قبل أي استيراد يلزم اعتماد ورقة المصدر وقاعدة اختيار العامل النشط، وتحديد ما إذا كانت أعمدة `Designation` و`Supplier` ستُحفظ، وكيف تُعالج التحديثات والحذف والتكرار. لا تغيّر سجلات سابقة تلقائيًا.

## 5. تجربة الاستخدام

- الإنجليزية افتراضية؛ العربية اختيارية، مع RTL كامل.
- واجهات بسيطة، خصوصًا للمشرف: الدخول → قائمة مسكن/فريقه → تعليم الغائب/الحاضرين → تأكيد وحفظ. تجنب إعدادات كثيرة وخيارات تقنية.
- صفحة الإعدادات للمستخدم تعرض تغيير كلمة المرور وتسجيل الخروج. تغيير الدور أو نطاق الإسناد ليس من إعدادات المستخدم.
- مدير المشروع وHR حسابان جاهزان بأسماء المالك المعتمدة؛ لا يطلب التطبيق إدخال اسم مدير المشروع أو HR عند كل دخول.

## 6. قبول الميزة

1. أول تشغيل يعرض الإنجليزية افتراضيًا، والقائمة المنسدلة لا تعرض حسابات معطلة.
2. `123456` يعمل ككلمة مؤقتة فقط، ثم يجبر المستخدم على تعيين كلمة جديدة قبل ظهور بقية التطبيق؛ لا يظهر النص أو الهاش في logs.
3. بعد إعادة تشغيل التطبيق، يظل المستخدم مسجلًا أو يطلب دخوله وفق مهلة قفل متفق عليها؛ لا يفتح التطبيق شاشة العمليات قبل المصادقة.
4. مشرف السكن يرى ويسجل مساكنه المعيّنة فقط؛ مشرف الموقع يرى فرقه فقط؛ المراقب لا يستطيع تنفيذ أي write حتى عند استدعاء المستودع؛ إدارة ترى الوظائف المخولة لها.
5. تغيير كلمة المرور يتحقق من القديمة، ويخزن salt/hash الجديد، ويلغي الجلسات/الأسرار المؤقتة.
6. فشل قاعدة البيانات أو الهاش يعرض خطأ واضحًا ويفشل مغلقًا؛ لا يتجاوز إلى واجهة التطبيق.
7. لا حاجة للإنترنت لتسجيل الدخول أو استخدام البيانات الموجودة محليًا.
8. اختبارات لكل دور على مستوى المستودع والواجهة، واختبارات hash والمهاجرات والاسترداد.

## 7. قرارات نفذها المالك

- اعتماد الأسماء الدقيقة لحسابي مدير المشروع وHR، وهل لهما صلاحيات متطابقة كما يقترح الجدول.
- اعتماد كلمة مرور مؤقتة `123456` وإجبار تغييرها عند أول دخول.
- استيراد XLSX وCSV على الجهاز مع معاينة، دون استخدام الشبكة.
- يستخدم `S/O` ككود موظف أولي بعد التحقق من التكرار، ويمكن تصحيحه يدويًا لاحقًا.
- لا يحتوي ملف القوى على ربط الفرق/المساكن؛ يبدأ المشرف بلا نطاق حتى يعيّنه
  المدير محليًا. يجب منع ظهور/كتابة نطاق غير معيّن.
- يظل التطبيق مقفلاً بعد كل تشغيل حتى تسجيل الدخول؛ الجلسة لا تُحفظ بين مرات
  تشغيل التطبيق.
