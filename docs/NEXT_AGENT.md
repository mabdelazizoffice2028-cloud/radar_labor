# تسليم العمل للموديل التالي

**تحديث:** 23 أكتوبر 2026. اقرأ هذا الملف ثم `DECISIONS.md` و`ROADMAP.md` وPRD وDESIGN قبل التعديل.

## توجيه المالك

- المطلوب إكمال تطبيق رادار ليبور بعد ظهور شاشة بيضاء في النسخة التي ثبتها المالك.
- V1 محلي ويعمل دون إنترنت وقت التشغيل. البيانات مشفرة، الخطوط والأيقونات محلية، ولا تبدأ مزامنة سحابية قبل طلب صريح.
- دعم العربية RTL والإنجليزية، مع تصميم Material 3 حديث وواضح ميدانيًا.
- وثّق كل مرحلة وأخطاءها وحلولها في `docs/` حتى يسلم كل موديل حالة العمل التالية بدقة.

## الوضع الحالي المعروف

- المشروع: `C:\my_apps\radar_labor`، الفرع `main`، والريموت كان `origin/main` على GitHub.
- Flutter 3.47.7 / Dart 3.13.5، Android SDK تحت `C:\Android\Sdk`، كاش Pub وGradle في `C:\devcache`، JDK 17. لا تشغل `flutter clean` أو `pub upgrade` ولا تحذف الكاش أو `.dart_tool`.
- جذر التطبيق صار يعرض تحميل/خطأ/إعادة محاولة، ثم لوحة رئيسية وتنقل عربي/إنجليزي. أضيفت شاشات العمال والفرق والسكن وإنشاء السجلات وتعيين الفريق والسكن للعامل وتسجيل حدث محلي للحضور بالموقع/غياب السكن.
- قاعدة البيانات Drift محلية ومشفرة عند الإقلاع باستخدام مفتاح في Flutter Secure Storage. تضم جداول الإعدادات والعمال والفرق والسكن وفترات العمل والأحداث. محرك الحالة والتاريخ ومستودع الأحداث موجودة؛ ربط كل قواعد PRD بالشاشات ما زال غير مكتمل.
- Cairo مع ترخيص OFL وMaterial Icons مضمّنان؛ التشغيل لا يجلب أصلًا بعيدًا. Manifest يحذف INTERNET وACCESS_NETWORK_STATE من نسخة الإصدار (Flutter قد يضيف INTERNET إلى نسخة debug لأدوات التطوير).
- README صار ثنائي اللغة ويذكر صراحة الميزات الحالية والنطاق المتبقي.

## التحقق وحالة APK

- Dart analyzer على ملف الواجهة بعد إضافة الإسناد لم يجد أخطاء ترجمة؛ أظهر 12 ملاحظة style/deprecation/async-context. Flutter analyze الشامل مرّ قبل تغيير الإسناد، ثم تعثر لاحقًا عند قفل Flutter SDK. التحليل ليس إثبات تشغيل.
- اختبارات المحرك/التاريخ وقاعدة البيانات نجحت سابقًا في سلسلة العمل (50 اختبارًا). لم تُعد بعد آخر تغييرات الواجهة.
- يوجد APK قديم في `build/app/outputs/flutter-apk/` (release 50,506,602 bytes؛ debug 180,820,482 bytes، تاريخ 23 أكتوبر). لا تسلمه: `aapt` كشف اسمه السابق `radar_labor` وأذونات سابقة، أي إنه لا يتضمن آخر تغييرات Manifest.
- بناء Release محدث فشل برسالة Gradle `The settings are not yet available for build` رغم وجود `android/settings.gradle.kts`. راجع B-003، وسجلات Gradle تحت `C:\devcache\gradle\daemon\9.3.1`، وتأكد أن عملية البناء تبقى في `C:\my_apps\radar_labor\android` بعد استدعاء wrapper.
- ADB لم يتمكن من الوصول إلى `.android` في مضيف التنفيذ؛ لذلك التثبيت والظهور البصري على جهاز المالك غير متحققين. لا تغلق B-001 قبل هذا الدليل.

## ابدأ من هنا

1. احصل على سجل Gradle كامل باستخدام wrapper من مسار Android الصحيح وشخّص سبب عدم تحميل Settings. البناء السابق وصل إلى إنشاء daemon ثم فشل قبل تجميع التطبيق؛ لا تبدأ بحذف الكاش.
2. أعد بناء Release وDebug إذا لزم، وقارن `LastWriteTime`، ثم افحص الحزمة بواسطة `aapt dump badging` (الاسم العربي، عدم وجود INTERNET/ACCESS_NETWORK_STATE في Release، وجود المكتبات/الأصول).
3. حاول ADB من بيئة المالك الطبيعية؛ لا تكرر تجاوز `.android` من sandbox. إذا تعذر الهاتف، وثّق بوضوح أن التشغيل الفعلي غير مؤكد.
4. أكمل PRD: تسجيل السكن/الإرسال والتصحيحات والتبريرات والحسم، تطبيق StatusEngine على لوحة الحالات، إدارة فترات العمل والمراجع، ثم فحوصات شاملة.
5. سجّل كل نتيجة في `WORKLOG.md` و`BUGS.md` و`ROADMAP.md` وحدث هذا الملف. بعد مراجعة كامل المستودع، أتم رفع GitHub الذي طلبه المالك. الريبو عام حاليًا؛ لا تغيّر خصوصيته دون موافقة.
